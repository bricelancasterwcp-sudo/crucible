## 4. Ops gotchas (recorded so nobody re-buys them)

- **`--jobs 8` OOMs the build at any cap tried (8G/12G); `--jobs 6` was the proven rung-0
  recipe (11G peak), `--jobs 5` used here.** The kill point is a deterministic memory burst
  in `build_units`, position-stable across caps. Build under
  `systemd-run --user --scope -p MemoryMax=12G -p MemorySwapMax=0` with `--jobs 5`.
- OOM-killed builds leak `/tmp/crucible-*` sandbox workdirs into tmpfs (RAM). Point the
  build's `TMPDIR` at a real-disk dir (`runs/tmp`) and clean after.
- `scripts/serve_model.sh` needs `.venv/bin` on PATH (bare `vllm` otherwise not found), and
  the SERVE table was missing the A2 proposer until commit `9586aa8` (2B-parity flags,
  confirmed live: bf16 1.5B serves clean at util 0.6).
- **One validation verdict is flaky at the hidden-only/equivalent boundary**: the rung-0
  guard rebuild reproduced the stream hash exactly but its census read `equivalent 541 /
  hidden-only 318` vs the original `540 / 319` — one borderline mutant flips between
  builds (both reasons invalid, task list unaffected, hash excludes counts by design).
  Known-class, count-level only; worth an eye at lock time.
- Pre-branch stream dirs fail the new `counts-named` precheck (no `stack-apply` key) until
  rebuilt/rewritten — `dd5912cddedc` was rewritten by the guard build and now passes. An
  old dir failing precheck before such a rewrite is stale serialization, not CONFOUNDED.
