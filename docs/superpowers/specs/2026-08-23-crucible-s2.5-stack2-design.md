# S2.5 — Rung-1 stream hardening: two-site (stacked) mutants

**Date:** 2026-08-23
**Status:** design approved by Brice (chat, 2026-08-23); this document is the written spec.
**Trigger:** ceiling pilot (§4.8.4) read **p0 = 0.767 > 0.70** on the rung-0 stream
(`streams/full/dd5912cddedc`, A_noMem, 1.5B-chat, 30 phase-1 tasks, K=8) — recorded in
`docs/findings/S2-ceiling-pilot.md §7–§8`. The stream is too easy for E1 to be detectable.

## 1. Protocol status: execution, not amendment

The hardening ladder is itself pre-registered (pre-reg §4.8.4): *"(i) two-site mutants;
(ii) MBPP+-only seeds; (iii) α-rename identifiers; (iv) tier-2 real repos — one rung at a
time, re-running the pilot; the rung reached is recorded and fixed at lock."* S2.5
implements **rung (i) only** (Brice ruling, 2026-08-23). No threshold, arm, endpoint, or
sampler changes. The single spec touch is a dated **clarification** to §4.8.3 (see §7
below), footnote-level under pre-reg §11.

## 2. Rulings (Brice, 2026-08-23, AskUserQuestion)

- **R-S25-1 — validity = components + composite.** Each of the two component mutations
  must be individually visible-killed AND the stacked composite must pass the full
  `validate.py` gate. A stack of one real bug + one equivalent mutation is single-site
  difficulty wearing a rung-1 label — the "value that looks like a measurement but is
  not" trap. Excluded by measurement, not assumption.
- **R-S25-2 — scope = rung (i) only.** No rung (ii) scaffold. If the re-pilot still reads
  p0 > 0.70, rung (ii) (MBPP+-only seeds) becomes its own design round.

## 3. The stacked mutant

- Composition of **two** single-site mutations from the **same family**, at **distinct,
  non-overlapping, non-nested spans**, in one unit — span intervals
  `[(start_line, start_col), (end_line, end_col))` must be disjoint under (line, col)
  ordering (nesting is a special case of intersection and is rejected by the same check). Same-family is forced by the
  pre-registered class = (unit, family) structure.
- **Identity rule unchanged:** `key = sha256(src_hash + "\n" + unified_diff(orig, stacked))`
  — same hash rule as single mutants, same fixed diff headers, no dates. The task is the
  bug-pair, keyed by content.
- The record carries both components' coordinates (operator, occurrence, span — ×2) and
  the site-set. `TaskSpec` grows the site-set (serialization round-trip exact, as today).

## 4. Composition algorithm (the wrong-site trap)

Applying component B's original occurrence index to A-mutated source is **unsafe**: a
mutation can create a new match for B's operator earlier in the AST visit order
(e.g. Add→Sub applied, then a Sub→Add component earlier in the file now has an extra
match), silently landing B on the wrong site.

**Invariant: a stacked mutant's diff touches exactly the two intended spans, or the pair
is dropped — never guessed.** Algorithm:

1. Order the pair: apply the **later-span** component to the original source first
   (existing `apply_spec`; its occurrence index is valid against the original).
2. Re-enumerate the **earlier** component's operator positions on the intermediate
   source; select the position whose span **exactly equals** the earlier span (a strictly
   later edit cannot move an earlier span). Not exactly one match ⇒ drop the pair,
   reason `stack-apply`.
3. Guards (each ⇒ not a mutant, like today's `make_mutant`): composite compiles
   (SyntaxWarning suppressed single-threaded, per R-T12-1); composite differs from the
   original **and from both singles**.

## 5. Validity, pairing, and cost

- Pipeline (approach A, approved): today's enumerate → sample → **validate singles**
  flow is untouched; valid singles per (unit, family) are then paired into stacked
  candidates; composites are sandbox-validated; `compose()` consumes stacked mutants at
  rung ≥ 1. Component validity comes free from the singles pass.
- Cancelling pairs surface as `equivalent` composites; hidden-only composites as
  `hidden-only` — the existing dropped vocabulary covers them. The **only new reason is
  `stack-apply`** (composition failed §4-style). Census keys seeded to zero, as always.
- Candidate pairs per (unit, family) are **capped (seeded sample, default 4)** to bound
  sandbox cost; the cap is a config knob if attrition bites.
- **Capacity (measured on the rung-0 build, 6,071 valid singles):** 333 (unit, family)
  classes have ≥ 4 distinct valid-mutant sites; C = 200 needed. Headroom exists and the
  per-family sampling cap can be raised if stacked-composite attrition cuts below C.
- Composite validations use the composite's own `n_killing_visible` / `kills_by_timeout`
  — §4.8.1 band definitions unchanged, computed from composite validations.

## 6. Class structure at rung 1

- Class-eligible = (unit, family) with ≥ 2 valid stacked mutants whose **site-sets are
  disjoint** (4 distinct sites per class).
- `_pick_pair`'s span-inequality generalizes to site-set disjointness; the non-timeout
  preference and the **seeded coin flip** for phase assignment survive unchanged (the
  §4.8.1(1c) timeout-band lever stays).
- **Novel phase-2 tasks are stacked too** — the control must match the treatment
  difficulty.
- Rung 0 behavior is **byte-identical**: the stacking branch is `--rung 1` on
  `crucible stream build`; guard test asserts a rung-0 rebuild at the pinned seed
  reproduces stream hash `dd5912cddedc`.

## 7. Pre-reg spec touch (applied with this commit)

§4.8.3 "Every class has `m1.site ≠ m2.site`" gains a dated footnote: at rung ≥ 1, sites
are site-*sets* and the assertion is **disjointness of m1's and m2's site-sets**. Old
wording left visible per §11 (non-silent amendment). Nothing else in §§2–7 changes.

## 8. Operational sequence and endpoint

1. Rebuild the full stream at rung 1 (C=200, pinned seed) — under the R-T2-6 memory cap;
   OS-detached (`setsid nohup` + pid file + `.DONE` marker) if projected > 2 h from a
   small-N dry run.
2. §4.8.1–3 structural pre-checks green (site-set disjointness assertion included).
3. Cheap §4.7 landing re-probe, 30 tasks, chat-served 1.5B (expect ~1.00 — stacking does
   not change module size; served-model **identity asserted**, GPU hygiene first).
4. Re-run the pilot **verbatim** (A_noMem, 30 phase-1 tasks, K=8, pinned sampler).
5. **The point estimate decides:** p0 ≤ 0.70 ⇒ rung fixed at 1 (recorded at lock);
   p0 > 0.70 ⇒ recorded, rung (ii) becomes its own design round. No re-rolls, no
   extension, no corpus swap after reading the number.
6. Records: findings (`docs/findings/` — extend S2-ceiling-pilot.md or new S2.5 file),
   CARRIED-DEBT at merge, SDD ledger throughout.

## 9. Testing (TDD; mutation-test the load-bearing lines, pyc purge discipline)

- Span-shift selection picks the intended site under the §4 trap (operator-creates-match
  case constructed explicitly, e.g. Add→Sub + Sub→Add).
- Non-overlapping / non-nested span rejection (nested-span case constructed).
- Pair sampling deterministic from seed; purpose-scoped RNG streams (`f"{seed}:<purpose>"`).
- Composite guards: equivalent composite dropped as `equivalent`; composite equal to a
  single dropped; `stack-apply` counted and named.
- Census completeness (every reason seeded to zero; `dropped` sorted), serialization
  round-trip with dataclass equality, schema-completeness test.
- Two full builds, same seed ⇒ same stream hash (rung 1); rung-0 hash regression guard.
- Sandbox-touching tests under `systemd-run --user --scope -p MemoryMax=4G -p MemorySwapMax=0`.
